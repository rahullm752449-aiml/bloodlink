1. Executive Summary & Architecture

The BLOODLINK frontend is engineered as a zero-dependency, mobile-first responsive web client designed for maximum accessibility during medical emergencies. It can be run directly from any modern web browser or built using modern bundlers such as Vite.

Key Architectural Principles

  • Zero Barrier Execution: Operates directly via standard modern browser features without mandatory local Node.js compilation.
  • Dual-Mode Data Layer: The API client automatically queries the live Flask backend (http://127.0.0.1:5000), while maintaining an in-memory & local-storage fallback with the official Ballari snapshot data when offline.
  • Emergency-First Visual Hierarchy: High-contrast crimson accents (#DC2626), pulsing status beacons, and instant 1-click dispatch workflows.
  • Privacy Safeguards: Mandatory donor phone number masking and strict consent-gated directory visibility.

2. User Interface Views & Workflows

A. Home & Emergency Dashboard (#home)

The landing view provides real-time situational awareness for emergency requesters and voluntary donors:

  • Network Status Counters: Displays total reported blood units available, active emergency requests, and verified voluntary donors.
  • Emergency Action Banner: Immediate high-visibility call-to-actions to either initiate an emergency request or search the blood bank network.
  • Demo Control & Reset: One-click safety reset to restore standard Ballari reference data during testing or demonstrations.

B. Blood Bank Directory & Interactive Map (#banks)

Provides healthcare workers and citizens with searchable directory access across Ballari district facilities:

  • Facilities Included: VIMS District Hospital, Indian Red Cross Society, Swamy Vivekananda Voluntary Blood Centre, and Jindal Sanjeevani Multi-Speciality Hospital.
  • Filter Controls: Instant filtering by City/Town and Blood Group (A+, A-, B+, B-, AB+, AB-, O+, O-).
  • Leaflet Map Integration: Interactive map markers bound to facility coordinates. Clicking a marker reveals the contact phone number and live blood unit counts.
  • Stock Availability Pills: Color-coded inventory indicators: Available (>5) Moderate (1-4) Critical (0)

C. Emergency Blood Request Wizard (#emergency-request)

The primary life-saving workflow of the application:

  1. Gemini AI Message Extractor: Requesters can paste unformatted WhatsApp/SMS forwarded messages. The assistant extracts patient location, blood group, required units, and urgency.
  2. Structured Request Form: Captures Patient Name, Required Blood Group, Units Needed (1–10), Urgency Level (Critical, Urgent, Standard), Hospital Name, and Verified Attendant Contact.
  3. Geolocation Pin Picker: An embedded Leaflet map allows requesters to tap the exact hospital location to generate coordinates for donor routing.
  4. Dispatch Gate: Dispatches alerts to matching registered donors and generates referral action links.

D. Voluntary Donor Directory (#donors)

Enables safe community donor search while safeguarding donor privacy:

  • Lists verified donors who have provided explicit consent for directory visibility.
  • Phone Number Masking: Sensitive phone numbers are masked (e.g., +91 9845X XXXXX) to prevent scraping and harassment.

E. Blood Bank Representative Portal (#bank-portal)

A lightweight operational interface for authorized blood bank staff:

  • Select facility and view live inventory breakdown across all 8 blood groups.
  • Direct unit adjustment buttons (+ and -) with immediate state synchronization.

3. Backend API Contract & Integration Matrix

/requests/<id>/send-alerts POST CSRF Token Dispatches matching donor emails and referral tokens

4. Deployment & GitHub Setup Guide

Running Directly in Any Browser (Zero Setup)

Double-click frontend/index.html in Windows Explorer or open it with Google Chrome, Microsoft Edge, or Firefox. The full user interface, search filters, interactive Leaflet map, and mock data engine run immediately without installation.

Publishing to GitHub as an Independent Repository

# 1. Open PowerShell and navigate to the frontend directory:
cd C:\Users\DELL\.gemini\antigravity\scratch\BLOODLINK\frontend

# 2. Initialize Git and stage all frontend files:
git init
git add .
git commit -m "Initial commit: BLOODLINK Frontend Application"

# 3. Rename branch to main:
git branch -M main

# 4. Connect to your GitHub repository and push:
git remote add origin https://github.com/YOUR-USERNAME/bloodlink-frontend.git
git push -u origin main

Deploying to Cloud Hosting (Vercel / Netlify / GitHub Pages)

  • GitHub Pages: Enable GitHub Pages in repository settings → Source: main branch → Folder: / (root).
  • Vercel / Netlify: Import the repository directly; no build commands required (Root directory: /, Output directory: /).
